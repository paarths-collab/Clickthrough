## 4. Pack feedback (real ones only)

1. `guide.md` Hard rule 3 / `uf-test` rule 4 ("Do not `goto` a deep URL... Only a flow whose step is 'changes the address' may type one"): nothing says how an emailed link counts. Reset and invite flows must open a URL from a mail. Had to guess: opened `/dev/mail`, clicked the link in the mail.
2. `uf-test` rule 8 ("Do not wait on 'network idle' or a fixed pause"): no guidance for "nothing must happen" checks on a background job, or jobs with no on-screen signal (F048, F059, F012, F043). Had to use bounded pauses and justify them myself.
3. `uf-test` rule 6 + `uf-evaluate` step 2 ("Reset data between flows if the tests do not do it themselves"): reset covers data only. A flow killed a shared service (worker); every later flow would fail for the wrong reason. Pack says nothing about checking/restarting services between flows. I invented: liveness check after each flow, fail that flow, restart before next.
4. `guide.md` Statuses + Failure classes: no status for "test passed for the wrong reason" (F009) or "cannot proceed because another flow's bug stops it" (F008). `blocked` only allows `ENV_BLOCKED`/`TOOL_GAP`. Guessed `unverified` and `fail`.
5. `guide.md` Failure classes: no class for a permission hole. In `not_allowed` flows the user *succeeds* at something forbidden; "FLOW_BROKEN: The user cannot finish, or the result is wrong" had to be stretched (F021, F060, F066). Also "Pick the class from what the user experienced first" hid the worse half of F012 (worker crash) behind MISSING_FEATURE.
6. `uf-flows` priority rule ("Set priorities now... Changing one later needs a reason") + verdict rule ("NOT READY: any P0 flow is fail"): a minor last step inside a P0 flow (F003 Back button) counts the same as a data leak, and a P0-grade leak found in a P1 flow (F042) does not count. No guidance to keep P0 flows to their essential steps, or to record severity separately from flow priority.
7. `uf-evaluate` step 4 ("Walk every P0 flow by hand, and every failed flow... a script that takes a screenshot at each step which you then look at"): with 38 flows this is the most expensive step. Does not say whether reading captured page text is acceptable, or how many screenshots must be looked at. "By hand" vs "a script" also reads as contradictory. I guessed and declared the shortcut.
8. `uf-discover` ("Do not submit forms just to collect messages" vs "Record the messages and empty states you meet while walking, and the ones the intent promises"): messages only appear on submit, so message surfaces came from reading page source. For S023 I had to tag `source: intent` ("promised, and you could not find it") from code alone, which sits badly with guide rule 4 ("Do not judge by reading source").
9. `uf-test` Evidence ("`<UF_EVIDENCE_DIR>/<flow-id>/final.png` and `failure.png`"): singular. Flows with two or three users have several pages. Guessed: one file per session plus the last page as `final.png`/`failure.png`.
10. `uf-test` rule 2 ("Playwright for anything with a browser or HTTP, and the official MCP client for MCP tools"; `run.test_command` singular): flows that mix MCP and browser steps (assistant acts, customer sees) are not covered. I ran the MCP client inside Playwright tests.
11. `.userflow/templates/report.md` Goals table ("One row per goal, one line per route"): flows of different variants share a route; no slot for the solo-rerun or walk result per flow, nor for "flows run" counts. Used one line per flow.
12. `.userflow/templates/report.md` header ("Commit: <sha> (<clean | uncommitted changes>)") and `new-run.sh` `uncommitted_changes`: preflight tells you to `npm i -D` Playwright, which dirties the tree. Unclear whether that is "uncommitted changes". `run.json` says false only because it was written before tooling was added.
13. `flows.yaml` template, `areas` status (`pending | mapped`): "finish one area at a time... The registry is your memory" - but there is no area status for tested/evaluated, so per-area progress cannot be recorded.
14. `uf-check.py`: `--stage discover` does not check that a surface's `area` exists in `areas`. The "goal ... has more than one route" print lists every normal/alternate flow once two route strings differ, so G10 printed seven entries, six with the identical route - noise. "no way in" warning fires only on the exact word `none`; pages reached only from an email or a dev page have no clean value for `reach`.
15. `collect-run.sh`: looks in `~/.claude/projects`, outside the project. Exits 1 for a subagent (as documented) but still stamps `ended_at`; fine, just note it reads outside the folder.
16. `uf-preflight` step 5 / `run.boot` ("one command that starts the whole stack"): nothing on keeping it alive between tool calls. My `nohup ... &` was killed when the tool call ended; had to use the harness's background runner. Harness-specific, but a one-line warning would have saved a restart.
17. Helper scripts: none errored unexpectedly. One self-inflicted miss: my rerun loop ran under zsh (the tool's shell, not bash 3.2) and did not word-split; reran under bash. Pack gives no ready command for "rerun each failure on its own".
